# Contributing

MarkAIOrg tracks product work in Linear. Use the Mark workspace for normal bug
reports, feature requests, and project planning rather than opening a GitHub
issue.

## Pull requests

- Use a Linear-generated branch name and include the Linear issue link in the
  pull request.
- Open pull requests against `main`; do not push directly to `main`.
- Keep each pull request focused and describe its purpose and scope.
- Include screenshots or recordings for user-visible changes.
- Report checks actually run, including linting, type checking, tests, and
  production builds as applicable.
- Describe database or API changes, security and privacy impact, deployment or
  migration steps, rollback instructions, and documentation changes.
- Never commit credentials, production data, or customer data.

Repository-specific `CONTRIBUTING.md` files take precedence over these defaults.
